# Glass Box 配置指南

这篇文档说明 Glass Box 中各类配置的职责、缺失影响和与原子能力的关系。Quick Start 只覆盖最小启动闭环；完整配置和排障应以本文为准。

## 配置分层

Glass Box 的配置可以分成三层：

- 必填配置：不配置会导致设备发现、用例执行或基础断言不可用。
- 推荐配置：不影响应用启动，但会影响录屏、投屏、音频、报告完整性或执行稳定性。
- 高级配置：服务 Agent、模型生成、TTS Provider、团队协作和跨平台适配。

## 最小可运行配置

如果目标只是跑通一个最小用例，至少需要完成：

- 设备连接能力：当前已有链路主要依赖 ADB 类设备能力，需要确保系统层面能识别目标设备。
- 默认设备角色：在设备管理中把常用 SN 固定为手机/伴侣设备或眼镜设备。
- 默认包名：配置手机/伴侣设备默认包名和眼镜默认包名，供启动、日志、环境切换、Mock、性能采集等节点复用。
- 用例协议校验：执行前先通过 `cases validate`，确认 JSON 结构、节点和变量引用有效。

## 设置中心

### 模型配置

模型配置用于文档转用例、对话式用例生成、LLM 节点等能力。

主要字段：

- 配置名称。
- 模型名称。
- Base URL。
- API Key。

未配置影响：

- 不影响手写用例、设备发现和普通用例执行。
- 会影响依赖模型的用例生成、文档转换和 LLM 文本生成节点。
- 如果模型服务返回 401/403、Access denied、overdue-payment、quota 等错误，GlassBox 会在 LLM 节点报告中标记为模型服务鉴权/账号状态问题，并保留 provider、model、Base URL 和 HTTP 状态，避免误判成业务断言不通过；需要修复设置中心配置或模型账号权限后再重跑。

### 环境配置

环境配置当前主要管理本机执行环境中的 ADB 路径。

主要字段：

- ADB 路径。

行为说明：

- 留空时 Glass Box 会自动查找可用 ADB。
- 显式配置后，桌面端和 CLI 都应使用同一个 ADB，避免多版本 ADB client/server 冲突。

未配置影响：

- 如果系统 PATH 或常见安装目录中能找到 ADB，通常仍可运行。
- 如果本机存在多个 ADB 版本，未固定路径可能导致设备反复断连、命令执行失败或 CLI 与桌面端使用不同 ADB。

### TTS Provider 配置

TTS Provider 用于动态语音合成节点。Flow 只传入动态文本，鉴权、音色、采样、噪声参数等应写在 Provider 的 URL、Header 或 Body 模板里。

主要字段：

- Method。
- 超时时间。
- TTS 接口 URL。
- Headers 模板。
- Body 模板。
- 音频 URL 字段路径。
- 输出扩展名。
- PCM 采样率、采样格式、声道数。

模板变量：

- `{{text}}`：原始文本。
- `{{textUrlEncoded}}`：URL 编码后的文本。
- `{{textJson}}`：JSON 字符串安全转义后的文本。

未配置影响：

- 不影响普通设备操作、ADB 节点、日志断言和手工音频文件 Mock。
- 会导致 TTS 合成节点无法动态生成音频。
- 如果响应字段路径或音频格式配置错误，后续音频 Mock、报告引用或转码可能失败。

### 桌面客户端自动更新

自动更新优先通过服务端检查接口决定版本和灰度，再使用服务端返回的 manifest、
ZIP、blockmap 三条受信 HTTPS 直链。只有旧服务完全不返回 `artifacts` 时才使用 ZIP feed
目录下载。推荐配置：

```json
{
  "updates": {
    "checkUrl": "https://updates.example.com/api/v1/desktop/updates/check",
    "channel": "stable",
    "checkTimeoutMs": 5000,
    "automaticChecksEnabled": true
  }
}
```

发行版官网通过 `GLASSBOX_RELEASE_PAGE_URL` 显式配置；未配置时不打开外部页面。
直链下载须通过 `GLASSBOX_UPDATE_TRUSTED_HOSTS` 提供逗号分隔的可信主机名；默认列表为空，未授权的下载和重定向被拒绝。

也可通过 `GLASSBOX_UPDATE_CHECK_URL` 或 `GLASSBOX_UPDATE_BASE_URL` 配置。环境变量
优先于设置文件；旧 `GLASSBOX_UPDATE_URL`/`updates.feedUrl` 仅在未配置检查接口时
兼容使用。未显式配置检查地址时禁用更新网络请求；配置后的默认通道为 `stable`。服务异常
不影响 App 启动和当前版本使用。

更新坚持两次点击：先“下载更新”，完成后再“重启安装”。任务、录屏、性能采集或
报告落盘期间允许下载，但会阻止重启安装。完整优先级、状态和服务端协议见
[公开源码与更新配置边界](public-source.md)。

设置中心 → 自动更新的正式界面展示当前版本、更新通道、自动检查开关、手动检查和
最近状态。版本号来自主进程 `app.getVersion()`，默认通道为 `stable`；用户可显式
切换到标注为测试通道的 `preview`，保存后立即检查。正式界面不提供
自定义 Base URL、Header、Body 或密钥编辑入口。内部调试配置与环境变量仍仅供
开发/MIST 注入，不会覆盖正式默认值。

自动检查开关持久化到 `updates.automaticChecksEnabled`，旧用户缺少字段时按开启
处理。关闭后不执行启动、激活或定时检查，但手动检查、下载与安全重启仍可使用。

### 设备管理

设备管理用于固定常用设备角色和默认包名。

主要字段：

- 手机/伴侣设备 SN。
- 眼镜设备 SN。
- 手机/伴侣设备默认包名。
- 眼镜默认包名。

行为说明：

- 顶部设备栏会周期性检测设备，命中已绑定 SN 后自动分配到对应栏位。
- `run case` 未显式传入设备时，CLI 会优先使用 Glass Box 设备管理中的绑定设备。
- 用例中的 `${defaults.phonePackage}` 和 `${defaults.glassesPackage}` 会读取默认包名。

未配置影响：

- 仍可能通过自动识别或命令参数执行，但稳定性和可复现性较差。
- 启动应用、写入测试文件、环境切换、日志采集、性能采样等能力可能缺少目标包名。
- 多设备同时连接时，未绑定角色容易选错设备。

## 外部工具配置

### ADB 类设备调试工具

当前已有设备调试链路主要围绕 ADB 类设备能力实现。

影响的原子能力：

- 设备发现。
- 命令执行。
- 日志采集。
- 截图。
- 文件推送和拉取。
- 应用启动、停止和环境切换。

建议：

- 团队成员尽量固定同一个 ADB 路径。
- CLI 输出中的 `adbPath` 应与设置中心一致。
- 遇到设备断连或版本冲突时，优先检查是否有多个 ADB 同时参与。

### 投屏和录屏工具

正式安装包从 `Contents/Resources/media-runtime/<platform>-<arch>` 使用内置 scrcpy、scrcpy-server 与精简 FFmpeg，不读取用户 PATH 中的 Homebrew 工具。

工作流勾选“执行时展示投屏”后，GlassBox 会等待内置 scrcpy 进入就绪状态。投屏属于辅助能力，启动失败不会把业务步骤误判为失败；执行结果会明确提示失败，并在本次执行目录写入 `*-scrcpy-mirror.log`，记录命令、退出码、信号、stderr 与恢复建议。

影响的原子能力：

- 设备投屏。
- 用例录屏。
- 报告中的屏幕录像附件。

未配置影响：

- 不影响无屏幕录制的用例执行。
- 勾选录屏或投屏选项时会失败或提示安装。

说明：

- 源码开发可显式配置 `SCRCPY_PATH`、`SCRCPY_SERVER_PATH`、`FFMPEG_PATH`；正式安装包缺少运行时会 fail closed，不提示普通用户自行安装。
- 后续支持其他系统设备时，应通过对应平台连接器提供等价能力。

## CLI Runner 配置

CLI 用于让脚本、CI 和 Agent 复用 Glass Box 执行引擎。

当前 `run task` 提交通路：

- Headless runner：CLI 从已安装的 Glass Box App bundle 后台启动 runner，并直接提交任务 payload。

通常不需要用户手动配置。

需要关注的场景：

- Agent 沙箱限制本地进程、ADB、scrcpy 或 localhost 时，应在沙箱外/提权运行同一条 CLI 命令。
- 已安装 App 更新后，直接使用新包内 CLI；如已有旧 runner/桌面端进程，先重启它们。
- CLI 任务提交由 headless runner 直接完成，桌面主进程不提供旧网络或文件桥接入口。

## 原子能力依赖关系

| 原子能力 | 依赖配置 | 未配置影响 |
| --- | --- | --- |
| 设备发现 | ADB 路径或对应平台连接器 | 无法识别真实设备 |
| 设备角色选择 | 设备 SN 绑定 | 多设备环境下可能选错设备 |
| 应用启动/停止 | 默认包名或用例内包名 | 无法定位被测应用 |
| 用例执行 | 设备、包名、有效用例 JSON | 执行失败或落到错误设备 |
| 日志采集 | 设备连接、日志权限、目标设备 SN | 日志断言和报告缺失 |
| 文本/JSON 日志断言 | 日志采集能力、断言配置 | 无法判断结果或超时 |
| 截图 | 设备连接、截图命令能力 | 报告缺少截图证据 |
| 录屏/投屏 | `scrcpy` 或平台等价工具 | 屏幕录制和投屏不可用 |
| 文件 Mock | 设备连接、默认包名、远端路径 | 文件无法推送到目标位置 |
| 音频 Mock | 设备连接、音频文件路径、格式参数 | 语音输入链路不可用 |
| TTS 合成 | TTS Provider、响应字段路径、音频格式 | 动态语音节点不可用 |
| LLM 生成 | 模型 Provider | 文档转用例、LLM 节点不可用 |
| 性能采集 | 设备连接、目标包名 | 无法采集目标进程指标 |
| Agent 执行 | CLI bridge、桌面端 runner | Agent 无法触发真实执行 |

## 推荐配置顺序

1. 先配置 ADB 路径或确认自动发现结果稳定。
2. 连接设备并固定常用 SN 角色。
3. 配置手机/伴侣设备和眼镜默认包名。
4. 用 `devices list` 确认 CLI 能读到同一批设备和默认配置。
5. 按需配置模型 Provider。
6. 按需配置 TTS Provider。
7. 需要录屏或投屏时，再安装并验证对应屏幕工具。

## 排障原则

- 先确认系统层面能识别设备，再看 Glass Box。
- 先跑 `components list` 和 `devices list`，再执行真实用例。
- 先通过 `cases validate`，再运行 `run case`。
- 多设备、多 ADB、多版本桌面端同时存在时，优先收敛到单一路径和单一运行实例。
