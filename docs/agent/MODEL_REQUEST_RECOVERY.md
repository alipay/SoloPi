# 模型请求步骤恢复

内置 Agent 参考 DeepSeek Harness 的持久化请求步骤边界恢复机制：
https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/llm/llm-retry

## 边界

仅重发当前失败的模型请求，输入沿用该步骤准备好的历史、模型和工具定义。已完成工具调用及其回执不重放。流式文本可以预览，但只有最终响应完整且校验通过后才提交历史并执行工具；重试前清空失败尝试的预览。重试元数据不进入模型消息，不增加一个要求模型“继续”的自然语言轮次。

AgentRuntime 关闭 requestModel 自身的重试，使用单一共享预算，避免连接重试与限流重试叠加。原始模型接口、摘要和其他直接请求调用方不隐式获得这套 Agent 步骤恢复策略。没有修改网关、鉴权、代理配置或强制常驻连接；失效 socket 的淘汰重建仍交给 HTTP 运行时。

## 有限重试

- 瞬时 socket/连接错误、响应超时、HTTP/明确上游 5xx、空响应和未完整结束的流：最多额外五次。退避基数为 0.5、1、2、4、8 秒，增加正负 10% 抖动。
- 限流沿用用户指定的 5、15、30 秒，最多额外三次。与上述错误共享全步骤五次上限，不因错误类型变化重新计数。
- 认证/权限、证书、余额/账单、输入预算、输出上限、工具参数错误不重试。明确上下文溢出仍走原有独立的有进展压缩恢复流程，复用当前步骤已有重试预算。
- 按结构化错误码、HTTP 状态分类，不匹配用户文案或上游错误消息正文。
- 用户停止、引导、新消息和应用退出沿用请求 AbortSignal，取消倒计时和发送。重启后不自动重放未完成步骤。

## 持久化与诊断

等待前将 scheduled 状态、次数、原因、到期时间和脱敏诊断写入会话；发送重试前写 started，成功、耗尽或取消后写对应终态。失败尝试只存结构化元数据，不存模型部分输出或凭据。落盘失败禁止再发请求。历史恢复步骤保留在 modelRecoveryHistory，当前在 modelRecovery；重试记录不投影为模型历史。

诊断事件 model.step-scheduled/started/completed/failed/cancelled 用步骤 ID 关联，会话 ID 和 clientRequestId 可关联每次底层请求原始错误。socket 字节数为连接累计值，不能当作本次响应字节或服务端接收证明。UI 显示实际错误类别、倒计时和次数，用户可停止。

每次重发仍可能产生模型费用。本地工具不重放不代表服务端推理恰好执行一次；本机制不适用于未纳入客户端执行账本的服务端副作用。

## 验证

tests/agent-model-step-recovery.test.mjs 覆盖预算、限流、持久化、取消、部分输出隔离、已完成写操作只执行一次，以及真实本地 HTTP 复用连接被关闭后新建连接恢复；不依赖外部模型、业务工具或设备。
