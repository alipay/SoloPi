# SoloPi 操作录制与历史用例导入

在用例库或文件夹的新建菜单选择「SoloPi 录制生成」或「导入 SoloPi 用例」。导入只新增草稿，不覆盖已有用例，也不改变现有执行器。

## 历史用例

选择 SoloPi 导出的单个用例 JSON。支持 `operationLog` 为对象或编码后的 JSON 字符串，也支持 `case-get` 的 `{success:true,case:...}` 回执。外置步骤文件须先通过 SoloPi `case-get` 导出完整结构。单个文件最多 10 MiB、2000 个操作。

命令行可以离线转换：

```sh
solopi-desktop cases import-solopi --file old-solopi-case.json --out new-desktop-case.json --json
solopi-desktop cases create --file new-desktop-case.json --library LIBRARY_ID --json
```

转换命令不访问设备、不修改用例库；输出文件已存在时拒绝覆盖。第二条命令才将新草稿加入指定用例库。`--phone SN` 可选，不从历史导出继承设备序列号。

## 新操作录制

录制控制已整合进 Desktop，不需要用户安装或填写 SoloPi CLI、Python、前置参数或录制组件包名。官方 SoloPi 手机组件随 Desktop 分发，开始录制时校验并准备，缺少或版本较旧时自动安装更新，不自动降级或卸载已有数据。只需按手机系统提示完成必要授权。

1. 在 Desktop 头部选择在线手机和被录制应用，打开「SoloPi 录制生成」。弹窗只读显示当前选择，不重复填写。
2. 填写用例名称，点击「开始录制」，等待确认后在手机中完成操作。
3. 点击「停止并转换」，确认操作数量与待处理节点，生成新草稿。
4. 修改待处理节点，补充业务断言，再运行验收。转换会在操作前插入通用 ADB 启动节点，使用录制目标包名先停止目标 App，再打开 Launcher 入口（am start -S -W，与 APK 录制准备的重启顺序一致）；不会自动补登录、深链或任意中途页面导航，录制若从中途页面开始仍需补齐对应前置。

### 录制起点

目前仅提供从应用首页开始录制。2026-10-21 按用户要求移除“前置命令进入页面，再录制操作片段”选项及输入框；不提供从当前页面录制。已有会话恢复及已生成用例保留原语义，不自动改写历史内容。

### 权限门禁

录制开始前使用手机 `harness/health` 检查内部 ADB、悬浮窗、后台运行、无障碍服务和电池优化白名单。全部已就绪只增加一次健康读取，不探测 root 或重写权限；状态查询、停止和导出不触发权限授予。

缺少权限时，仅当 `id -u` 或经授权的 `su -c id -u` 确认 uid=0，才尝试补齐可自动授予的悬浮窗、无障碍和电池白名单。无障碍设置使用当前 Android 用户，保留其他服务。每次授予后回读手机端真实状态，命令退出成功不代表权限已生效。内部 ADB 仍复用既有连接准备与 RSA 回执验证，不写入密钥或更改自定义连接地址。

非 root、root 未获授权、厂商限制或自动授予后仍缺权限时，Desktop 弹窗列出缺失项和处理方式，不派发录制，也不执行前置命令；处理后重新开始会再次检查。弹窗提供“我已授权，直接进入”：显式点击后仅跳过本次 Desktop 权限及应用列表可见性预检，继续内部 ADB 准备、手机录制启动与前置命令；手机端真实失败仍正常反馈。该选择不保存为默认配置、不写入生成用例，也不影响原生回放。应用列表不可见默认也会拦截，不猜测厂商私有授权接口。root 不能保证省掉 RSA 系统确认或所有厂商授权。原生回放同样检查其执行模式所需权限（headless 为 ADB 和无障碍），保持既有权限边界。

开始后会话冻结本次手机、目标应用和前置命令；修改头部不会把停止请求发给另一台手机。未选择手机/应用时禁止启动，离线、安装和权限错误在入口反馈；未发出录制请求的前置失败释放本次设备占用。

录制与测试共用设备互斥。仅停止本入口拥有的会话，不接管其他用户的录制。启动/停止结果不明时保留会话和占用；重新打开入口可恢复处理。正常退出有界尝试停止录制；失败状态保留，下次进入需核对恢复，不能宣称已停止。停止成功但读取导出失败时，可重试读取，不重新录制。

## 转换边界

- 无额外参数的 `CLICK` 使用现有手机 UI 元素点击；支持 resourceId、text、description 定位，不把 XPath 或相对点击位置静默改为屏幕中心。
- `BACK` / `HOME` 生成手机按键节点，`SLEEP` 保留毫秒时长。
- `INPUT` 生成输入节点，但清除原输入内容；须填写文本或变量、确认定位与输入方式后解除待处理标记。加密操作不尝试解密。
- 循环、条件、脚本、断言、滑动、额外参数、SoloPi 动态变量和高级设置，当前需要人工转换或核对。不能用「元素存在」冒充原断言，也不会自动执行导入脚本。
- 所有源操作按文件顺序占一个节点。不支持的操作有明确待处理标记，执行前拒绝整条用例；请替换或显式删除该节点。不要直接清除标记来假装转换成功。
- 草稿不复制原始操作 JSON、输入值或脚本，只保留来源哈希及动作序号。历史导出文件由用户保管。

协议基线为 SoloPi `3b8c146ab80b0325aece65b8ef417136c251869c` 的类型化录制协议；Desktop 已将所需 ADB、loopback HTTP、会话确认及用例导出逻辑实现为内部 Node 模块。内置手机组件为官方 v1.0.2，清单记录包名、版本、SHA-256、签名证书及来源；构建前验证完整性，Mac/Linux 打包显式包含相同资源。不会降级为视频识别或手工回放。
