# 支付宝搜索输入往返

首页开始，模型在“搜索框 / 更多 / 我的”中选择搜索入口；固定步骤输入预先冻结的“天气”；模型再在当前搜索页的“返回 / 清空 / 输入框当前文字”中选择返回。搜索确认按钮不进入动作候选，不提交搜索。

包含 `open-search`、`leave-search` 两段连续决策。真机已观察到：输入后第一次点击搜索返回只退出联想状态、清空查询，仍在搜索页；第二次返回才回首页。因此整条流程可能包含三次模型点击，不能把第一次返回的执行成功当作已经回首页。

`leave-search` 用搜索返回按钮识别两种搜索页状态，输入候选不绑定“天气”文字；第二种状态的清空按钮可能消失，输入框可能显示推荐提示。每次均从新观察构造候选，不复用旧节点。完成条件始终是首页“更多”出现，之后仍由独立 Oracle 验收。

固定输入和四条 checkpoint 保持冻结。输入后的 Oracle 仍要求 text=天气；搜索按钮的两条断言只检查描述，不代表检查 enabled 状态。每段 `maxSteps=3`，退出阶段允许同动作最多重复两次，`maxNoProgressSteps=1` 保留；第二次返回必须建立在真实页面进展上。

清理仅验收首页“更多”，不会在未知页面盲目返回。若流程未回到首页，清理失败需通过新的真实观察处理。配置来自 2026-09-28 已观察的支付宝 12.12.30.8000 页面，本轮相同配置的规则与 Laya 各3次完整运行均通过；这仍不证明模型优于完整 resourceId 规则。详细结果见 `docs/fastpath/PUBLIC.md` 与公开计时摘要。
