# solopi-harness-desktop media runtime

solopi-harness-desktop release packages embed a self-contained, version-pinned media runtime at:

`resources/media-runtime/<platform>-<arch>/`

Required layout:

```text
bin/scrcpy[.exe]
bin/ffmpeg[.exe]
bin/adb[.exe]
share/scrcpy/scrcpy-server
lib/                         # platform runtime libraries when required
LICENSES/                    # scrcpy, FFmpeg and dependency notices
manifest.json                # generated by verify-media-runtime.mjs
provenance.json              # pinned upstream versions and archive hashes
```

End users do not install Homebrew, scrcpy or FFmpeg. Maintainers build or obtain a
self-contained runtime, then materialize it with:

```bash
npm run media:prepare -- --source /absolute/path/to/runtime
```

Production packaging fails closed if the runtime is absent, still references
Homebrew paths, or lacks notices. Development may use `SCRCPY_PATH`,
`SCRCPY_SERVER_PATH` and `FFMPEG_PATH` explicitly.

The bundled FFmpeg must include both `libopus` and `libspeex` encoders.
Speex is stored in an Ogg container (`.spx`), supporting 8/16/32 kHz and mono/stereo.
Build inputs include a static Speex library and its BSD license.

## Linux FFmpeg distribution gate

Linux packages require an LGPL-2.1-or-later FFmpeg build with explicit
`--disable-gpl --disable-nonfree --disable-version3`. A GPL/nonfree build is
rejected; changing the product's Apache license is not a workaround.

The runtime must contain `ffmpeg-build.json` (`media.ffmpeg-build.v1`), recording
its exact executable SHA-256, configure arguments, build recipe, and each source
component's version, upstream URL, source archive and license SHA-256. Put exact
corresponding source archives and the recipe in `sources/`; retain all upstream
copyright/license notices in `LICENSES/`. Include static codec dependencies in
the source records too. Build evidence must match the shipped binary, not another
version. `scripts/ffmpeg-compliance.mjs` verifies these materials before importing
a runtime or packaging Linux. Native encoder/decoder smoke checks are still
required on the target baseline. Keep these materials with every distributed
runtime; they do not change the application's own license.

Use `record-ffmpeg-build.mjs <runtime> <source-records.json> <recipe>` on the build
host to generate the record from native `-version`/`-L` output. Source records
provide `name`, `version`, `url`, local `archive` and `license` paths; codec
libraries also provide `buildRecipe` with the commands used to build them.
`verify-ffmpeg-capabilities.mjs <ffmpeg> [existing-h264.mp4]` checks actual audio
round-trips, video generation/decoding, PNG extraction and copy trimming without
devices. Linux package verification runs these checks on a matching native host.
Cross-platform manifest verification reports native checks as pending; it cannot
substitute for executing the target binary.

The Linux x64 recipe keeps zlib dynamically linked for PNG decoding; the target
baseline therefore needs system `libz.so.1` (`zlib1g` on Debian/Ubuntu), in addition
to its glibc libraries. The Debian package declares this dependency. These system
libraries are not copied into the FFmpeg source record as bundled codec libraries.
