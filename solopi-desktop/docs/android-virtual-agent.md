# Android Agent 后台屏幕实验

本功能为实验构建，默认关闭。关闭时继续使用现有主屏方式；开启后，新启动的 Android Agent 任务创建独立虚拟屏，手机端读取无障碍信息，并在需要时用本地 OCR 补充文字。Agent 根据观察选择候选，设备端复核后执行。无法创建或确认副屏时，任务停止，不自动切换到主屏。

## 准备

1. 连接并解锁 Android 12 或更新版本的手机，开启 USB 调试，安装带有以下构建标志的 SoloPi 调试包。已发布的旧 APK 不一定具备实验协议。实验助手使用设备的 shell 权限创建受信副屏，具体设备和 App 是否支持仍需实测。
2. 在 SoloPi 中完成首次初始化，按系统提示启用该安装包对应的无障碍服务，并确保 SoloPi 内部 ADB 可用。保留已有正式应用和数据；签名不一致时不要直接卸载，先处理签名或使用隔离的测试包。
3. 电脑需要 Python 3.9 或更新版本，且桌面进程能通过 `python3` 找到它；也可以在启动桌面端前设置 `SOLOPI_HARNESS_PYTHON` 为 Python 可执行文件的绝对路径。Harness 源码随桌面包提供，当前不内置 Python 解释器。可先执行 `python3 --version` 检查。
4. 在桌面端选择该 Android 手机，并配置可用的 Agent 模型。模型认证失败需要检查服务账号和配置；副屏本身不能修复模型服务的授权错误。

桌面打包会把 Harness 的 Python 源码及资源放在应用资源目录中。开发验证曾用隔离测试包核对 36 个文件。随后从固定源码构建媒体运行时，补齐 Git LFS，并生成了 Apple Development 签名的 macOS ARM64 测试包：包内 36 个 Harness 文件与源码一致，实际运行包内 FFmpeg 的编解码及 PNG 截帧检查通过，签名和对应源码检查也通过。首次启动时，终端安全服务拒绝创建 Electron Helper；管理员放行后，测试包可启动并显示 Agent 界面。在隔离配置、脚本决策器和一台 Android 真机上，签名包完成两次受控点击，固定页面状态验收通过并确认副屏清理；同一次运行的四组截图与观察文件哈希均核对通过。该任务在创建副屏前的系统日志记录了钥匙串提示及后续允许，用户没有看到弹窗；任务随后继续，界面总等待为 18 分 25 秒，副屏会话报告耗时 27.028 秒，不包含此前等待。提示如何呈现及是谁处理的无法确认，这不能视为首次使用体验已解决。系统评估此前拒绝了该开发签名包；正式签名、公证及分发验证仍未完成。

例如从仓库构建隔离测试包（需要 Android SDK 和 JDK 11，并先将 `JAVA_HOME` 指向 JDK 11）：

```sh
cd solopi-app
./gradlew --no-daemon '-Dorg.gradle.jvmargs=-Xmx2048m -Dfile.encoding=UTF-8' :portal:assembleDebug -PfastpathDebug -PvirtualScreenOcr -PvirtualScreenExperimental
adb install -r portal/build/outputs/apk/debug/portal-debug.apk
```

`-PfastpathDebug` 使用 `com.alipay.hulu.fastpath` 测试包名，避免覆盖正式 SoloPi；如已有同名包但签名不同，安装会失败，需要先处理签名。端口以该安装包的控制服务配置为准。当前桌面调试版默认连接正式包 `com.alipay.hulu` 的 23342 端口；使用测试包时可从桌面启动环境指定 `SOLOPI_ANDROID_CONTROL_PACKAGE` 和 `SOLOPI_ANDROID_CONTROL_PORT`。这两个变量只选择控制服务，不改变被测应用。

## 使用

1. 打开桌面端「Agent 对话」→「请求设置」，勾选「使用后台屏幕（Android 实验功能）」并保存。
2. 如需回归验收，在同一设置中添加固定验收条件，填写无障碍节点的 `resourceId`、文字或描述作为定位条件，并填写该节点的预期文字。条件会在任务开始时冻结；结束时由 Harness 独立重新采集和判断，不由模型填写。目标必须可见且位于当前窗口，无法定位、几何不明、被其他窗口遮挡或证据不完整时为未测试。
3. 新建对话，描述要打开的 Android 应用和只读任务；如使用逐次确认，按界面提示确认启动和动作。开关修改只影响之后启动的任务，运行中的屏幕模式不会切换。
4. 对话顶部显示后台屏幕状态，可展开查看最近画面。画面请求失败或超过五秒没有新画面时显示“画面暂未更新”，保留的图片标明是最后一帧；后续取得新画面后恢复显示。执行耗时较长时也可能出现该提示，不单凭它判断设备断连。Agent 可使用当前可操作节点、只读的可见节点文字、手机端 OCR 文字和有限的页面滚动；只读节点用于理解页面，不能作为动作目标。动作只接受本次观察中的候选 ID，不接受模型指定的坐标或屏幕 ID。
5. 结束、取消或出错时，桌面端会尝试释放该任务的副屏。正常完成后，对话显示固定验收结论及本地 HTML 报告路径；报告保存观察、整屏截图、动作回执和清理结果。未配置条件、任务未完成、节点不可用或证据缺失时为未测试。清理未确认时不要重复操作；可以在原对话点击「重试清理」。桌面重启后可用保存在本机加密存储中的原会话信息尝试恢复；如果凭据不可读取或设备不能确认，状态仍为清理未确认。若屏幕已经清理但本机恢复记录删除失败，检查本机凭据存储后点击「重试删除恢复记录」；该操作不会再向手机发送动作。本对话在记录删除前不启动新任务，避免覆盖原状态。

手机本地完成 OCR；页面节点和 OCR 文字会作为上下文发送给当前选择的模型服务，截图用于本地预览和证据，不作为图片发送给模型。请先确认所选服务以及页面内容适合发送。截图和回执可能包含私有信息，保留在本机及设备的会话证据目录中，不应直接公开。

Agent 查询和回调的应用日志不记录请求参数、页面正文或会话令牌。一次真机测试使用合成令牌验证 Agent 请求未出现在日志中，并用普通请求确认日志采集有效；这不等于第三方应用或系统的所有日志都已审查。

手机端能力中的 `virtualOcrBundled` 仅说明构建是否包含 OCR，不保证每次识别都成功。桌面会根据实际观察提示“手机 OCR 不可用”或“本次 OCR 未就绪”；前者需要带 OCR 的构建，后者可以重新观察。OCR 不可用时只剩无障碍节点，不能假定无文字页面仍可操作。

## 能力和限制

- 当前点击、节点滚动以及空节点页面上的受限上下滚动由手机端执行；文字识别可能有误，目标不唯一、被遮挡、页面过期或校验失败时拒绝。输入、返回等动作尚未在此模式提供。
- 当整屏或当前窗口画面全黑时，可能是系统保护，也可能是真正的空白页面；两种情况均停止并报告无法确认。目标区域被涂黑时也会拒绝点击。Android 真机已验证整屏受保护及普通页面上的受保护弹窗；对后者，打开弹窗的动作已提交但后续页面无法确认，报告会保留这个不确定状态。这个保守规则不等于能识别所有厂商、所有形式的受保护窗口；黑色普通内容也可能被误判。
- 应用窗口和画面均绑定到任务持有的运行时屏幕 ID；窗口变化后重新观察。虚拟屏幕并非独立的安全沙箱，厂商行为、应用兼容性及主屏焦点影响仍需逐设备测试。
- 后台屏幕方向或尺寸发生变化时，本次会话失效，需要结束后重新开始；恢复原方向不会恢复旧目标。真机将测试副屏旋转后，观察约 0.4 秒返回 `virtual_display_geometry_changed`，预览也拒绝返回旧画面；恢复方向后同一会话仍被拒绝。另一次快速旋转再恢复的测试中，旧目标返回 `stale_observation`，设备时间线没有动作派发，副屏清理确认。该保护不表示已支持横竖屏切换后继续同一任务。
- Android 可能复用并迁移已在主屏运行的同一应用任务：在一次受控测试中，将同一测试应用启动到副屏后，主屏露出了先前的应用。因此不能保证用户在主屏使用的同一应用保持原有页面；使用前应考虑这一影响。另用两个不同包名、外观相同的受控测试应用同时在主副屏显示相同按钮，副屏点击进入子页面时，主屏仍显示原按钮；这只证明该次跨屏动作没有误点主屏。
- 应用可能自行将新页面打开到主屏，SoloPi 不能阻止系统或应用的这一行为。动作提交后，若副屏窗口不可见且连续两次观察到同一应用在主屏活动，任务会提前停止并提示核对；不会对主屏执行下一步。若系统无法提供足够的窗口信息，仍按稳定观察超时处理，不能保证每次跨屏都被识别。
- 动作已提交但回执或动作后的绑定观察未确认时，本次会话进入只读状态：允许重新观察和清理，不再提供可执行候选，也不接受新动作。当前协议未能明确证明失败发生在派发前时，同样保守停止；请核对实际页面后开启新任务。发送成功不代表业务结果正确，必须使用预先固定的验收条件独立判断。
- 受控应用已在一台 Android 真机验证节点操作、OCR 点击、固定条件的独立判断和清理：预期“已支付”而页面实际“已取消”时，报告为失败；取消任务时报告为未测试。微信在旧副屏实现上存在页面可能落在主屏的不确定性；新的受信副屏已完成一轮限定只读动作的真实模型摘要验证，细节见下文。当前副屏验收只支持任务结束时的无障碍节点文字检查，并非现有 `verify-run` 的完整多检查点流程。
- 桌面 Agent 运行时、Harness 桥接和真机副屏已通过一次脚本化决策器的端到端接线验证：节点点击后选择 OCR 候选，固定订单状态验收通过并确认清理。决策器是测试脚本，不是模型，不能作为模型自动完成任务的证据。
- 使用本机 Ollama 的 `llama3.2:3b` 在受控 App 上进行了三轮真实模型联调，三轮均未完成两步目标：一轮启动后提前结束，两轮未进入目标页面，其中一轮的无效工具参数被拒绝。已启动的副屏均确认释放；固定条件没有误报通过。这只反映该模型和这三种提示下的试验结果，不代表其他模型的表现。
- 使用此前获授权的内部兼容模型 `Qwen3.8-Flash-Next`，通过桌面 Agent 运行时与真机副屏执行相同受控流程三轮：三轮均自主完成节点点击和 OCR 点击，固定订单状态验收通过，副屏清理确认。每轮五次模型请求；会话报告耗时 33.96、35.31、34.57 秒。实验将可启动应用和应用列表限制在受控 App，属于单流程、小样本接线验证，不代表任意 App 的成功率；该运行不是通过桌面界面发起，也不证明另一份模型配置的授权问题已解决。
- 在隔离测试配置中再从桌面 Agent 对话发起同一受控流程三轮，逐次确认和本对话自动执行均验证过：三轮均通过固定验收并确认清理，可在界面查看副屏画面和打开报告。测试配置同样限制应用列表与启动目标；其中逐次确认的耗时包含人工确认等待，不应与自动执行直接比较。
- 同一内部模型还运行了一轮受控业务错误场景：模型选择对应场景并进入订单详情，读取到“已取消”；固定预期是“已支付”，独立验收判为失败。该轮四次模型请求，会话报告耗时 30.23 秒，副屏清理已确认。
- 在受控禁用场景的另一轮模型实验中，订单入口禁用，两个其他入口都显示“查看”；模型猜选了错误入口并尝试重新进入场景，测试因此被人工停止。这次不能作为通过案例。随后增加了保守规则：同一页面中标签、描述和控件类型相同、无法区分的点击节点不再成为动作候选；目前还没有利用父子语义区分同名入口，因此可能拒绝本来可用的节点。
- 规则增加后，真机上两个同名候选均不允许点击，强制提交候选编号被 Harness 拒绝；设备只记录了进入场景的两次派发。对同一冻结页面观察的一次离线模型测试选择停止，没有返回点击调用。随后的一轮受控应用真机模型复测中，模型进入禁用场景后说明目标不可操作且同名入口有歧义，主动停止；报告为未测试、清理已确认，整个过程只执行了进入场景的两次点击。这是单轮验证，不能推断所有歧义页面都会得到同样结果。此前被人工中断的模型任务原报告仍为未测试、清理待确认；设备时间线记录其后空闲看门狗释放了会话。另以脚本化决策器复测节点点击和 OCR 点击，固定验收通过并确认清理。
- OCR 文字重复时，桌面端会提前标记为只读，手机端仍独立检查文字和位置。对一次真机采集的受控页面离线重放，三条同名 OCR 文字均不再成为动作候选；随后一轮真机正常流程仍通过节点点击、OCR 点击和固定验收。该检查按文字保守去重，可能拒绝可通过上下文区分的文字，也不能保证模型不会误选其他文字。
- 在一轮受控真机流程中人为注入一次预览请求失败，状态出现“暂未更新”并在后续新画面到达时恢复，固定验收通过、清理确认。该实验使用脚本化决策器和注入故障，不代表已验证物理断线或界面刷新帧率。
- 同一真机分别安装带和不带 OCR 的副屏测试构建：无 OCR 构建明确返回 `ocr_unavailable`；带 OCR 构建首次观察返回过 `stale_observation`，重新观察后返回 `current`，两个会话都已清理。这是设备端及桥接测试，不代表每次识别都成功。
- 若启动时的 OCR 明确报告画面过期，Harness 最多自动补采两次新观察，不重发动作，也不在 OCR 未打包时重复采集。补采失败则继续报告不可用或停止，旧目标不会恢复使用。一次真机冷启动中，首次为 `stale_observation`，自动补采一次后为 `current`；设备记录了两次观察、零次动作派发，清理确认，该次电脑端启动耗时 5.940 秒。
- 副屏模式只向模型提供屏幕操作和只读证据工具。若模型启动副屏却在尚未尝试动作时结束，执行器最多提示其复核一次，并允许它说明当前观察已经足够或无法继续；已尝试的动作不会由该机制重发。历史观察在发送模型时可缩成证据引用，完整原文和动作回执仍在本地。本机小模型复测仍未完成微信点击，不能将提醒机制当作任务成功的保证。
- 副屏任务使用专用提示，保留授权、候选绑定、不重发和独立验收规则；主屏提示不变。针对一次真实失败批次的离线重放，采用合成系统前缀且不包含工具定义时，输入估算从 7,970 降到 4,693 tokens；两条旧观察变为证据引用，最新观察完整保留。该数字是估算值，不代表实际模型 token 或速度。修复后本机模型的一轮微信复测不再出现该预算报错，但只完成了启动和观察，没有点击朋友圈；副屏清理确认。
- 只读节点和 OCR 文字按应用窗口及几何位置筛选；节点还须可见且不是密码，OCR 中已识别为密码区域的文字也会排除。其他窗口遮挡或窗口几何信息不完整时，相应文字不会发给模型。在一次真实受控弹窗截图的离线重放中，弹窗窗口之外的 11 条 OCR 文字均未发送；另一轮正常页面真机流程通过。这些检查不能保证识别同一窗口内部的所有遮挡或未被系统标记的敏感内容。
- 不提供关于速度提升的承诺；建屏、OCR、执行和等待耗时会因设备和页面而变化。
- 报告的阶段耗时使用单调时钟：电脑端记录启动、动作、结束观察与验收、清理和会话总时长；每次手机观察记录页面树与画面绑定、PNG 编码写入、OCR 与复核、观察总计，以及电脑拉取和校验截图。建屏和应用启动提交是会话级数据，随观察重复显示，不能累加。启动提交不是页面就绪；启动、动作和最终验收都包含观察，观察总计又包含内部阶段，这些重叠区间不能相加。未提供字段的旧 APK 显示“未采集”。
- 最终固定验收仅使用无障碍节点，因此新版手机端在这次观察中跳过 OCR，但仍采集和校验页面树、窗口与截图。任务过程中的观察与 OCR 操作不变；证据记录 `ocrSkipped`。旧 APK 不支持时仍会执行 OCR，不改变验收条件。
- 在一台 Android 真机上，将短空闲超时的测试控制进程强制结束后，设备端看门狗结束了会话并释放副屏；这不等于已验证物理拔线或所有厂商的断连恢复。
- 真机上关闭控制进程的输入管道后，副屏约 2.6 秒内释放，报告确认清理。另一次强制结束控制进程的测试，将设备空闲超时临时设为 10 秒，约 10.9 秒后观察到副屏消失和租约释放；正式会话配置为 5 分钟，不能将测试时间当作正式清理时效。进程被强杀前已生成本地报告，结果为未测试、清理为待确认；桌面重启后不能仅凭进程消失就把待确认改为成功。

- 随后收紧了启动失败行为：副屏创建或初始观察失败时立即结束本轮，不让模型自动重试或继续执行同批动作。用不存在的受控测试包进行的真机反例中，仅发送一次启动请求，后续点击未执行，结果为未测试，清理确认且加密恢复记录已删除。
- 针对这个本地模型，另用两条不含真实用户数据的合成页面测试参数提示：原提示与增加 ID 格式说明的提示各测试四次，两种提示都没有生成有效工具调用。因此没有把这项提示变化作为修复，也不能用它推断其他模型的表现。
- 又使用六种合成页面及候选正逆序，分别用中英文提示让本机模型在有限 ID 和 `abstain` 之间选择。中文 12 次正确 6 次、错误选择动作 6 次；英文 12 次正确 7 次、错误选择动作 5 次。所有请求仅在本机离线评测，未操作手机；无目标和歧义场景出现猜选，因此没有把该选择器接入执行链路。这是小规模诊断，不代表其他模型的表现。
- 同一新链路的反例把预期状态固定为“已取消”，而页面实际为“已支付”；独立验收报告失败，屏幕清理确认。它验证的是单条固定条件不会因模型或脚本结束而自动通过。
- 助手 Binder 交接入口仅在实验构建中启用，并由系统 `DUMP` 权限、调用者身份和一次性口令限制；普通构建的入口处于禁用状态。单设备交接测试验证了错误口令、重放、错误归属和错误屏幕拒绝，以及正确建屏和释放；曾出现一次助手提前退出。另由不同 UID 的测试进程持有 Binder，验证创建、释放、清理和关闭四种调用均被拒绝，原副屏仍可由正确所有者释放。一次故意结束应用进程的测试观察到其持有的副屏被系统移除。测试仅覆盖这些路径，不能代替完整的安全和多设备验收。
- 会话层两次真机探针使用错误令牌尝试观察、点击和结束，均收到 `owner_mismatch`；正确所有者仍可观察原页面并结束会话，其中一次设备时间线确认没有动作派发。
- 启动组件的 Java 类名可以与应用 ID 使用不同前缀；SoloPi 仍通过系统为指定应用解析启动组件，并将启动绑定到该应用包和任务副屏。一台真机上用隔离测试包验证了这种组件可以启动并采集页面，未对任意第三方应用作兼容性保证。

一次开发期真机抽样中，相同受控应用的「进入标准订单流程」：主屏连接 4.91 秒、点击 6.43 秒；副屏启动 4.22 秒、点击 4.57 秒。两次均为单轮、非模型控制，包含各自链路的采集和等待，不能据此推断稳定的性能差异。该设备在副屏启动前后系统报告的全局焦点发生变化，不能保证所有手机上的主屏焦点不受影响。

另做三轮交错抽样：同一手机、同一受控 App，重置测试 App 后点击「标准订单流程」，固定检查页面状态为 `ORDERS`，两种方式均为 3/3 通过且清理成功。主屏启动、动作、整段中位数分别为 4.918、6.366、15.804 秒；副屏分别为 3.535、4.876、11.135 秒。重置时间不计入；主屏使用桌面录制链路，断言后有额外观察，副屏使用独立最终验收并进行 OCR，因此这不是相同实现的纯粹推理速度对比。三轮仅供诊断，也不代表微信或其他设备的性能。

另一轮脚本化桌面接线测试，在副屏执行节点点击和 OCR 点击并验收订单：报告会话总计 27.75 秒，电脑端启动 3.89 秒，两次动作分别 5.05 秒和 13.32 秒，最终观察与验收 3.96 秒，清理 1.47 秒。手机端四次观察的 OCR 与复核分别约 0.01、0.26、2.71、2.62 秒。单轮数据只用于定位耗时，不代表模型速度，也不能与上面的单步主屏抽样比较速度。

在一台 Android 真机上对受控应用首页的固定验收做了前后三次测量，六次均通过并确认清理。优化前最终观察及验收为 1.750、1.734、1.753 秒；跳过这一步不使用的 OCR 后为 1.030、1.034、1.067 秒，中位数分别为 1.750 和 1.034 秒。该对照没有模型调用，仅衡量最后验收阶段，样本很少且前后顺序固定，不能推断整条任务或其他设备的加速幅度。
