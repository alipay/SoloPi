# 用连线表达并行监听

不需要额外的并行控制或汇合节点，也不需要新的状态组件。复用已有断言，从上一动作拉出多条线，再把各个断言连接到同一个后续节点：

```text
上一动作 ┬→ 页面断言 ─────────┐
         └→ 日志文本提取断言 ─┤→ 下一动作
```

多条无条件出线自动启动并行；共同后继自动等待所有分支满足后执行一次。IF 的 true/false/error 分支仍按原有选择语义执行。当前支持单个只读断言构成的分支；有副作用的命令不能被这种监听分叉意外重复派发。

## 复用日志文本断言

日志文本提取断言新增节点级配置 `config.observationMode`：

- 省略或 `latched`：保持原行为，命中一次后保留通过结果。
- `latest`：持续提取最新值，用原有 `extractRegex`、`expectedText`、`matchOperator` 和 `caseSensitive` 判断；直到所有其他分支通过且当前最新值也通过时，才放行共同后继。

此选项在已有日志文本断言的侧栏直接编辑，保存在当前用例步骤，不改全局组件。没有新增组件 kind 或解析器；提取及比较均复用已有实现。提取变量和可选截图继续按配置生效。持续模式需要完整的并行连线，单独放在串行链上会提示结构错误。

正则必须覆盖全部状态，捕获目标值，而非仅匹配就绪事件。配置示例（仅属于用例，不是框架默认业务规则）：

```json
{
  "type": "component",
  "componentId": "component-tts-text-assert",
  "device": "glasses",
  "config": {"assertBlocking": true, "observationMode": "latest"},
  "inputs": {
    "extractRegex": "GPK_VoiceAnimStateMachine.*transitionTo \\S+ -> (\\w+)",
    "expectedText": "VOICE_LISTENING",
    "matchOperator": "equals",
    "caseSensitive": "true",
    "captureScreenshotOnPass": "false",
    "extractVariableEnabled": "false"
  },
  "timeoutMs": 45000
}
```

框架没有内置上述 tag 或状态。状态回退时，先前通过不再有效；同批日志中的就绪后回退也不能被锁存。初始状态未知时不会放行。页面与收音日志任意顺序到达均可；一次性断言先通过后会保留结果。

监听使用任务已有日志流，不新增 ADB 采集进程。各分支尊重有效 clearBeforeStart 配置：false 回读当前用例开始后的留存日志，包括之前动作产生的结果；true 从本分支开始检查时的边界等待新日志。状态监听未配置该字段且组件也没有默认值时，保留最近动作窗口。组件默认值仍由步骤 inputs 覆盖，并行不会忽略此配置。持续状态只采用序列最新的匹配值，旧就绪不能覆盖之后的回退；不会读取上一条用例的日志。

允许回读较早结果不证明它由最近输入产生；需判断最新输入时，按用例需求设置边界及通用匹配条件。接收序列不提供服务端请求身份保证。

汇合总上限取本组各分支完整执行预算的最大值。LLM 分支的完整预算为累计日志等待 + 每候选各次模型请求及有限重试间隔 + 稳定性观察/截图/执行后延时，不能只用节点的日志超时作为组总上限。当前每次模型请求独立计时、每候选最多3次请求、最多3条候选；20秒日志等待与15秒模型请求保持独立，模型阶段不消耗日志等待额度。完成即汇合，不固定等满上限；预算明细写入执行回执与超时诊断。一次性断言本身仍按自己的配置超时。超时、分支失败、日志证据中断或停止均清理本组监听和未完成断言，不执行共同后继。触发动作成功与分支失败分别记录，不能把后续等待失败误记为此前动作执行失败。

状态指本机已收到的最新日志，不是设备端的原子输入许可。框架不会把动画状态自动解释成服务端可接受语音。

普通文本/JSON 分支的预算同样包含日志等待后的稳定观察及执行后延时；最新值监听没有这段完成阶段。父级上限在最大完整预算之外另留 1000ms 调度余量，避免先注册的父计时器取消恰好观察满窗的负向断言。负向条件仍须观察完整节点时长，窗口末尾的禁止事件仍失败，不提前放行。并行截图在所有分支结算后由父级采集；数值 `postPassObserveMs: 0` 与字符串 `"0"` 都表示不额外等待，不影响负向断言自身时长。显式 `logReadScope: "action"` 从触发动作前建立的序列读取，保留在分支注册前已到达的响应。

先前引入的 `parallel`、`join`、`log_state` 节点类型已撤回，不再由 UI、CLI 或 Agent schema 提供；第17条用例已按本设计迁移。历史测试中固化额外节点的断言已替换为连线自动汇合、复用已有组件、两种先后顺序、回退/恢复及失败清理回归，没有通过删除有效状态检查来放宽结果。

2026-10-23 验证：相关109项通过；以测试进程并发4跑完整套1913项，1902通过、11项原有跳过、0失败。类型检查、生产构建、语法和diff检查通过，构建保留3条既有体积警告。高并发默认跑法曾触发文件监听测试5秒超时，原测试未修改，独立及最终全量均通过。未重跑真实设备用例，未发布安装包。

## 画布标识

连线编辑时即时展示配置关系：分叉处显示“并行 N 路”，各分支及汇合连线显示 `&&`，共同后继显示“&& N 路全部满足后继续”。这些标识表示配置有效，不表示业务断言已经执行通过。

缺少共同后继、分支配置不符合要求时，在相关节点显示红色警告及具体原因，连线显示红色虚线。修复连线后自动切换为正常标识；多个并行组分别判定，IF 的选择分支不会被标成 AND。界面提示与执行器使用同一结构校验。标识仅用于展示，不写入用例、组件或保存的连线；执行耗时标签仍保留。
